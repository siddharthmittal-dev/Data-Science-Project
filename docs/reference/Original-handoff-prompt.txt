You are continuing the Agentic Clinic project in this repository.

## Project context

Agentic Clinic is an academic clinic-coordination application using synthetic data only. It is not a diagnostic, prescribing, emergency-care, or real-patient system.

The finalized frontend design is **Terra**. Sage and Pulse were alternative design concepts and should not be treated as separate backends.

The current Terra frontend is a browser-only prototype. Do not claim that backend, authentication, Oracle Cloud, RAG, or machine-learning features are implemented unless they are actually present and tested.

## Selected ML model

Use:

`amazon/chronos-bolt-small`

Purpose:

- Forecast daily scheduled appointment volume
- Forecast clinic-wide or authorized clinic-level aggregates
- Predict a seven-day horizon
- Support capacity-planning insights only
- Never make medical, triage, diagnosis, or automatic patient-access decisions

Implementation requirements:

- Use CPU-compatible inference first
- Pin dependency versions
- Record model revision and checksum
- Cache model weights
- Keep inference out of the HTTP request thread
- Run inference through a background worker/job queue
- Bound CPU, memory, execution time, and concurrency
- Add job status: queued, running, succeeded, failed, stale
- Make forecast jobs idempotent
- Persist model metadata and data-version metadata
- Add a deterministic fallback based on the previous corresponding weekday
- Label the fallback as baseline, never as Chronos
- Return a safe 503 or stale result when the model is unavailable
- Never allow negative appointment counts in displayed output
- Use the same transformation for inference, evaluation, and display

## Forecast data design

Create a reproducible synthetic appointment generator with:

- Several months of daily data
- Weekday/weekend patterns
- Holiday and clinic-closure days
- Appointment capacity limits
- Appointment status transitions
- Controlled random disturbances
- Fixed random seed
- Dataset version/hash
- Generation timestamp
- Scope and date range metadata

Forecast target:

`daily scheduled appointment count`

Clarify that scheduled appointments represent planned clinic capacity and are not equivalent to true patient demand.

Prevent leakage by using an explicit observation cutoff. Future cancellations or updates must not be included in historical input for a forecast.

## Model evaluation

Implement chronological rolling-window evaluation:

1. Define multiple historical cutoff dates.
2. Forecast a seven-day horizon for each cutoff.
3. Run Chronos-Bolt Small.
4. Run the previous-weekday baseline on the same windows.
5. Compare actuals with predictions.
6. Calculate:
   - MAE
   - Optional RMSE
   - Bias
   - Per-horizon MAE
   - Prediction interval coverage
   - Prediction interval width
7. Store all evaluation metadata.
8. Do not call intervals calibrated unless evaluation proves calibration.
9. Clearly state that synthetic-data results do not prove real-clinic accuracy.

## Care assistant

The assistant must be controlled and non-autonomous.

Flow:

1. User asks a question.
2. Server validates intent and permissions.
3. Assistant returns an explanation or a proposed action.
4. Any appointment mutation is shown as a proposal.
5. User explicitly confirms.
6. Server revalidates permissions and current state.
7. Server executes an atomic transaction.
8. Audit event is recorded.

The assistant must not directly change appointments based only on generated text.

Start with deterministic responses and extractive answers. Add a local model only behind a provider adapter after evaluation.

## Oracle Cloud deployment

Target Oracle Cloud Infrastructure.

Preferred academic prototype topology:

- One OCI Compute VM
- Private PostgreSQL service or protected database deployment
- Private persistent storage for documents, indexes, PostgreSQL data, and model cache
- Reverse proxy exposing only HTTPS
- Background worker as an internal service
- OCI VCN, security lists, and NSGs
- Host firewall
- Restricted SSH
- HTTPS certificates
- Secret configuration outside source control
- Automated backups
- Restore test
- Resource monitoring
- Log rotation

Before provisioning, verify current OCI Always Free eligibility, ARM compatibility, regional capacity, quotas, storage limits, and billing requirements.

Do not assume Always Free guarantees. Do not enable paid resources without explicit approval.

Never expose publicly:

- PostgreSQL
- Worker ports
- Model service ports
- Internal document storage
- Debug endpoints
